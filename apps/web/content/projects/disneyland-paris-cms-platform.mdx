As a freelance Technico-Functional Consultant at Disneyland Paris, I was the cross-functional technical project lead and application support reference for a CMS platform used simultaneously by Disney's Europe, Americas, and Asia entities.

## Context

The CMS was shared infrastructure, not a single-team tool:

- multiple regional entities (Europe, Americas, Asia) relied on the same platform
- each region had its own priorities, stakeholders, and release calendar
- any change had to account for Run (keeping the platform stable) and Build (shipping new functionality) at the same time

## Problem

Coordinating a shared platform across regions and disciplines made it hard to:

- **reconcile conflicting requirements** from different regional entities in a single backlog
- **keep Product, Design, IT, and QA aligned** on the same priorities and status
- **ship changes safely** when a single issue could affect multiple regions at once
- **trace decisions** after the fact, due to inconsistent governance documentation

## My Role

Cross-functional technical project lead and application support: gathering requirements from regional stakeholders, writing functional specs and User Stories, coordinating Product/Design/IT/QA, and owning migration planning and risk analysis for platform changes.

## Problems Encountered

- Requirements from different regional entities sometimes conflicted, with no single backlog reconciling them.
- Cross-team coordination was fragmented — each team had its own view of priorities and status.
- Releases and migrations carried real risk, since a platform issue affected multiple regions simultaneously.
- Governance and change history were not consistently documented, making past decisions hard to trace.

## Solutions Built

**Requirements & backlog.** Ran structured requirements-gathering sessions with each regional stakeholder group and consolidated them into functional specs and User Stories in a single governed backlog.

**Delivery cadence.** Set up and ran Agile/Scrum ceremonies (planning, backlog grooming, reviews) to keep Product/Design/IT/QA aligned on the same priorities and delivery calendar.

**Risk management.** Built migration plans with explicit risk analysis before any platform-level change, including rollback steps.

**Governance.** Documented decisions and process changes to give the client's teams a clear, traceable change history.

## Business Value Delivered

- **Stable Run across three regions** — no disruption to daily operations while Build work continued in parallel.
- **Lower migration risk** — releases and migrations delivered against a documented, risk-assessed plan instead of ad hoc coordination.
- **Cross-team alignment** — Product, Design, IT, and QA working from one shared backlog instead of four separate views.
- **Traceable governance** — decisions documented and searchable well after the sprint that made them.

## Technical Stack & Why Each Tool Was Selected

- **JIRA** — chosen as the single backlog and issue tracker so every region's requirements and every team's tasks lived in one place instead of scattered spreadsheets and email threads.
- **Confluence** — used for functional specs, migration plans, and governance documentation, since decisions needed to be traceable well after the sprint that made them.
- **Agile/Scrum ceremonies** — the delivery framework chosen specifically because it gave recurring checkpoints (planning, review) where conflicting regional priorities could surface and get resolved early, rather than at release time.
